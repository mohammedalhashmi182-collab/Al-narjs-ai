# المنتج والبنية

| طبقة | حدود المسؤولية |
| --- | --- |
| Narjis Core | الإعداد والتسجيل في `src/core`، orchestration في `src/automation`، وخدمات المشاريع والفوترة والمبيعات والوكلاء في `src/services`. تبقى نماذج قاعدة البيانات والاشتراكات القائمة المصدر التشغيلي. |
| Narjis Managed SaaS | `src.main:app`، قوالب الويب والبوابة ومركز قيادة المالك. يظل `alnarjisai.com` النطاق المعتمد. |
| Narjis White-Label | `src.white_label.app:create_app` مدخل مستقل، يدير ملف إعداد أسماء المؤسسات والنطاقات والألوان والشعارات ومفاتيح إتاحة الصفحة وحالة الترخيص. |
| Narjis Standalone | يستخدم المدخل المستقل بوضع `standalone` ويقبل مستأجرًا واحدًا. التوسعة إلى نواة كاملة تحتاج بنية نشر وبيانات وأسرارًا خاصة بالعميل. |

مصدر حالة الدفع هو سجل الدفع الداخلي بعد تحقق المزوّد. مصدر العروض والباقات هو [الكتالوج البرمجي](../../src/services/catalog.py) مع كتالوج Drive مرجعًا تجاريًا. يستمر CRM في تجميع الفرص في `AcquisitionLead`، وتبقى بيانات عميل المشترك في البوابة مرتبطة بمشروعه. يجب أن تأتي هوية المستأجر في أي واجهة تشغيلية لاحقة من المصادقة وتفويض المورد. اختيار العلامة من النطاق يحدد صفحة عامة فقط.

تعمل العلامة المستقلة في خدمة يمكن تشغيلها دون استيراد التطبيق المدار ودون اتصال بقاعدة البيانات. توسيعها لإدارة أعمال العميل يتطلب اختبار صلاحيات القراءة والكتابة والتصدير والملفات والعمليات الخلفية في PostgreSQL على جميع الموارد. راجع [بنية الترخيص](white-label.md) و[مراجعة الأمن](security-and-privacy.md).

## مصفوفة القبول

| شرط المنتج الكامل | ما يجب التحقق منه في المراجعة |
| --- | --- |
| الهوية البصرية والأصول الأصلية | معاينة الأصول والرئيسية بالعربية والإنجليزية وفي شاشات صغيرة وكبيرة. |
| كل الواجهات ثنائية اللغة | تغطية الرئيسية واللوحة والصوت ضمن هذه الشريحة. تدقيق كل الصفحات والفوترة والبوابة بشكل مستقل قبل الإطلاق الكامل. |
| صوت قابل للاستخدام بلا كشف أسرار | اختبار حالات المتصفح ورفض الإذن والمسار النصي. اللهجة والجودة والتدفق الحقيقي يحتاجون بيئة مزود اختبار وميكروفونًا. |
| بيانات تشغيلية حقيقية | اتصال اللوحة بمصادر النظام. تحقق بيئي من إعدادات الخدمات ومطابقة الإيرادات في Staging. |
| تنسيق الوكلاء ومنع تكرار العمل | اختبارات التملّك والحالات والصلاحيات. تحتاج رحلة مشروع كاملة تسليمًا فعليًا من مزود اختبار. |
| سلامة الدفع واتساق الأسعار | محاكاة الاتجاهات المختلفة وتحديث الحالة. يوجد اختبار حي سابق أكده المالك. |
| White-Label وعزل العملاء | عزل واجهة العلامات واختبارات البوابة المعنية. يلزم تأسيس عزل نواة العمل قبل توفير بوابة ومراسلة ودفع في هذه الخدمة. |
| Standalone | بدء خدمة الهوية بإعداد مستقل دون أسرار أو قاعدة بيانات النرجس. تشغيل SaaS كامل للعميل خارج نطاق هذه الشريحة. |
| إطلاق القنوات | اختبار سلامة مسارات المراسلة المتاحة. Instagram ونوافذ إرسال Meta ومزامنة Drive بحاجة إلى صلاحيات وأدلة تشغيل. |
| إصدار قابل للنشر | توقف المراجعة قبل الدمج عند أي بوابة غير ناجحة أو غير مثبتة. انظر [الدليل](release.md) و[نتائج الاختبارات](test-evidence.md). |
